H4G CTF Challenge Analysis Workbench
====================================

The Docker build contains the integrated forensic/reverse-engineering toolchain,
the Hack4Gov challenge-pack-aware extensions, and the Solve Assistant.

MAIN MODULES
------------
http://127.0.0.1:8000/
    Hack4Gov module home.

http://127.0.0.1:8000/challenge-library
    Challenge Library: browse the bundled HACK4GOV CHALLENGES folder, inspect
    folder inventory, and import a file/folder directly into the artifact graph.

http://127.0.0.1:8000/workbench
    Artifact Workbench: files, PCAPs, WAV/audio, images, PDF, email, archives,
    binaries, QR/barcodes, steganography, damaged-header repair, coordinates,
    USB HID/keylogger captures, recursive extraction, multi-protocol fragment
    correlation, flag detection, decoder lab, and evidence timeline.

http://127.0.0.1:8000/solve-assistant
    Solve Assistant: paste the challenge wording and correlate it with the
    current artifact tree. Local mode stays inside Docker. Optional AI mode can
    reason over a bounded evidence summary and saves a "how it was solved"
    report. It also distinguishes clean CTF flags from noisy binary brace matches.

http://127.0.0.1:8000/case-search
    Case Search: search across imported challenge artifacts for analyst names,
    Message-IDs, metadata tools, timestamps, secrets, hostnames, and printable
    strings from binary files.

http://127.0.0.1:8000/visual-crypto
    Visual Crypto Lab: combine two image artifacts using difference, multiply,
    screen, lighter, darker, 50% blend, and XOR modes. Results return to the
    normal artifact graph for additional analysis.

http://127.0.0.1:8000/web-lab
    Authorized Web Lab: scoped GET/POST/HEAD/OPTIONS requests, headers, body,
    response time, flags, and redirect-chain inspection. localhost and RFC1918
    private IP ranges are allowed automatically. Public hosts must be explicitly
    added to the authorized scope in the Web Lab before requests are sent.


RUN WITH DOCKER DESKTOP
-----------------------

1. Start Docker Desktop.

2. Open PowerShell:

cd "C:\Users\user\OneDrive\Desktop\STUFFS\ctf-challenge-analysis-toolkit"

3. Use the integrated-workbench branch:

git checkout feature/integrated-workbench
git pull origin feature/integrated-workbench

4. Make sure Git LFS challenge binaries are present locally:

git lfs install
git lfs pull

If the Challenge Library reports Git LFS pointer files, run git lfs pull again
before rebuilding Docker.

5. Rebuild because the Docker image contains the analysis tools and bundled
   challenge examples:

docker compose down
docker compose build --no-cache

6. Start:

docker compose up

7. Open:

http://127.0.0.1:8000

To stop, press Ctrl+C or run:

docker compose down


OPTIONAL AI SOLVE MODE
----------------------

The Solve Assistant works without AI in Local Reasoning mode.

To enable AI mode for the current PowerShell session, set your API key as an
environment variable BEFORE starting Docker. Do not put the key in GitHub or in
the source files:

$env:OPENAI_API_KEY="your-api-key-here"
docker compose up

Optional model override:

$env:H4G_AI_MODEL="gpt-5.6"

The browser never receives the API key. The backend sends only the challenge
prompt plus a bounded evidence summary when AI mode is selected. Local mode does
not send challenge content outside the workbench.


ANALYSIS TOOLCHAIN
------------------

file, strings, xxd, exiftool, binwalk, foremost, tshark, radare2, rabin2,
readelf, objdump, nm, zsteg, steghide, upx, ffmpeg, ffprobe, sox, pdfinfo,
pdftotext, pdfimages, bsdtar, and zbarimg.

The workbench also contains Python analysis modules for Base64/Base32/hex/URL
and XOR decoding, whitespace steganography, CSV-aware GPS coordinate analysis,
email header extraction, damaged-header repair/signature scans, embedded HTML/
CSS data-URI extraction, visual cryptography, case-wide evidence search, USB HID
decoding, clue reasoning, and stricter flag-candidate filtering.


RECOMMENDED HACK4GOV WORKFLOW
-----------------------------

For one of the bundled example challenges:

1. Open Challenge Library.
2. Import the relevant file or its containing folder.
3. Open Artifact Workbench and use Analyze Entire Challenge.
4. Inspect Findings, Tool Output, Preview / Hex, Decoder Lab, Case Search, and
   Flag Candidates.
5. Open Solve Assistant and paste the COMPLETE challenge wording. This is
   important for riddle/knowledge challenges where the prompt itself supplies
   the decisive clue.
6. Select Local Reasoning or AI mode and review the saved solve report.
7. Validate the proposed flag against the required flag format before submitting.

Example clue-style flow:

Challenge prompt
  -> identify meaningful clue
  -> compare with artifact evidence
  -> use background knowledge only where clearly needed
  -> reject noisy/non-printable regex candidates
  -> format the candidate exactly as H4G{...}
  -> save the explanation as a Solve Report

For image-share challenges, open Visual Crypto Lab and combine the relevant image
artifacts, then analyze the generated PNG artifacts in the Workbench.

For a web challenge, use Authorized Web Lab. Private CTF IPs such as 172.16.x.x
are already within local/private scope. Public hosts must be explicitly added to
Authorized Scope. The Web Lab does not provide credential stuffing or destructive
off-scope actions.


FLAG FALSE-POSITIVE CLEANUP
---------------------------

The Hack4Gov runtime now rejects generic flag candidates containing non-ASCII or
non-printable binary data. On startup it also removes old unconfirmed candidates
from ctf.db that fail the stricter detector. Confirmed flags are preserved.


WORKSPACE RECOVERY
------------------

The workspace database persists through Docker restarts. At startup, the app
repairs valid moved artifact paths and removes stale database trees whose files
no longer exist. Re-uploading a stale artifact rebuilds its backing file and
analysis tree automatically.
