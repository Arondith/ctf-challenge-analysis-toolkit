H4G CTF Challenge Analysis Workbench
====================================

IMPORTANT
---------
The full Analysis Tools list (file, strings, xxd, exiftool, binwalk,
foremost, tshark, radare2, rabin2, readelf, objdump, nm, zsteg,
steghide, and upx) is installed inside the Docker image.

The integrated workbench now runs those tools from the browser. You should not
need to leave the application and copy normal analysis commands into PowerShell.

For uploaded PCAPs the workbench can automatically run protocol statistics,
endpoints, TCP conversations, DNS/HTTP inspection, payload checks, TCP-stream
reassembly/flag scanning, and transferred-object extraction. Recovered objects
are sent back into the same recursive artifact-analysis pipeline.

The built-in demo is separated from real challenge flags, and uploading a real
artifact automatically removes demo evidence first.

If you run the backend directly from a Windows Python virtual environment,
most Linux forensic utilities will appear as "missing" because they are not
installed on Windows or are not on your Windows PATH.


RECOMMENDED: RUN WITH DOCKER DESKTOP
------------------------------------

1. Install and start Docker Desktop for Windows.

2. Open PowerShell and go to the project folder:

cd "C:\Users\user\OneDrive\Desktop\STUFFS\ctf-challenge-analysis-toolkit"

3. Pull the latest changes if needed:

git pull

4. Build the analyzer image with all CTF tools:

docker compose build --no-cache

5. Start the application:

docker compose up

6. Open this in your browser:

http://127.0.0.1:8000

Use "Upload + Analyze" or drag a challenge file into the page. The workbench
will triage the file and run the relevant allow-listed tools inside Docker.

Use "Analyze Entire Challenge" to run relevant analysis across the current
artifact tree. "Deep file carving (Foremost)" remains a manual action because
it can create many recovered files.

To stop the application, press:

Ctrl + C

Or from another PowerShell window run:

docker compose down


AFTER PULLING NEW GITHUB CHANGES
--------------------------------

When the Dockerfile changes, rebuild the image before starting it again:

git pull
docker compose down
docker compose build --no-cache
docker compose up


OPTIONAL: NATIVE WINDOWS / PYTHON MODE
--------------------------------------

You can still run the web application without Docker, but the external Linux
forensics/reverse-engineering tools may show as missing.

From this folder:

C:\Users\user\OneDrive\Desktop\STUFFS\ctf-challenge-analysis-toolkit

run:

python -m venv .venv

Then:

.\.venv\Scripts\python.exe -m pip install --upgrade pip

Then install the Python requirements:

.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt

Then start the integrated server:

.\.venv\Scripts\python.exe -m uvicorn backend.workbench:app --host 127.0.0.1 --port 8000

Open:

http://127.0.0.1:8000

For the complete analysis toolchain, use the Docker method above.
